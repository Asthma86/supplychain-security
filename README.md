# Detection Engineering & Supply Chain Security

Двухконтурный программный комплекс защиты контейнеризированной инфраструктуры и цепочек поставок ПО.

---

## 1. Описание проекта

Комплекс объединяет два контура информационной безопасности:
1. **Трек 1 (Detection Engineering & Stateful CEP)**: Потоковый темпоральный коррелятор многоэтапных атак (Recon -> Exploit -> PrivEsc -> Persistence), компилятор правил Sigma в Wazuh XML и централизованное хранилище телеметрии OpenObserve.
2. **Трек 2 (Supply Chain Security & AST Analysis)**: Карантинный прокси-шлюз перед Verdaccio, алгоритм выявления тайпосквоттинга на базе метрического дерева Буркхарда — Келлера (BK-Tree) с матрицей смежности клавиатуры QWERTY и статический деобфускатор AST Constant Folding.

---

## 2. Архитектура базового стенда (КТ-1)

В рамках Контрольной точки 1 развернут базовый стенд в `docker-compose.yml`:
* **OpenObserve**: Легковесное высокопроизводительное хранилище JSON-телеметрии и алертов безопасности.
* **Wazuh Manager**: Сбор событий auditd/syslog, декодирование и сопоставление правил.
* **Falco**: Сенсор системных вызовов ядра контейнерной среды.
* **Verdaccio**: Локальный изолированный кэширующий реестр пакетов.
* **Supply Chain Analyzer**: Изолированный контейнер с точкой монтирования `tmpfs` (64 МБ, `noexec,nosuid,nodev`) для безопасного статического анализа пакетов в памяти.

## 3. Результаты обязательных замеров «До» (КТ-1)

### Трек 1: Базовый замер по дампам OTRF Mordor (`reports/baseline-before-sigma.json`)
* **Датасет**: 5000 событий (4500 легитимного фона healthcheck/сборки + 500 событий атак в 10 сценариях).
* **Инструмент**: Стандартный атомарный набор правил Wazuh + валидатор Hayabusa.
* **Результаты**:
  * **False Positive Rate (FPR)**: `31.13%` (высокая зашумленность от команд `curl`, `whoami` из healthcheck).
  * **False Negative Rate (FNR)**: `27.60%`.
  * **Precision**: `20.53%`, **Recall**: `72.40%`, **F1-Score**: `31.99%`.
  * **Корреляция многоэтапных атак**: `0%` (атомарные правила без Stateful CEP Engine не связывают шаги Recon -> Exploit -> PrivEsc -> Persist в цепочку).

### Трек 2: Базовый замер по выборке пакетов PyPI/npm (`reports/baseline-before-supplychain.json`)
* **Датасет**: 50 пакетов (25 легитимных + 10 открытых вредоносных + 10 обфусцированных + 5 тайпосквоттинг).
* **Инструмент**: Голый сканер GuardDog + базовые сигнатуры YARA-X без AST-деобфускатора и без BK-Tree.
* **Результаты**:
  * **Baseline Recall**: `40.00%` (соответствует условию ТЗ $\le 62\%$).
  * **Пропуск обфусцированных закладок**: `10 из 10` ($100\%$ пропуск полезных нагрузок, спрятанных за `chr()`, `getattr()` и конкатенацией строк).
  * **Пропуск тайпосквоттинга**: `5 из 5` ($100\%$ пропуск пакетов вроде `reqursts`, `numpi` из-за отсутствия метрического дерева BK-Tree).

## 4. Структура репозитория

```text
supplychain-security/
+-- docker-compose.yml          # Манифест развертывания ядра инфраструктуры
+-- requirements.txt            # Зависимости Python
+-- config/                     # Конфигурации сервисов (Verdaccio, Falco, OpenObserve)
+-- track1_cep_sigma/           # Модули Трека 1 (CEP-движок, правила Sigma)
+-- track2_supply_chain/        # Модули Трека 2 (BK-Tree, AST-деобфускатор, анализатор)
+-- datasets/                   # Датасеты OTRF Mordor и сэмплы пакетов
+-- reports/                    # Артефакты замеров «До» (baseline-before-*.json)
+-- rules/                      # YARA-сигнатуры анализаторов
+-- scripts/                    # Скрипты генерации датасетов и автогрейдера
+-- tests/                      # Модульные тесты pytest
```
